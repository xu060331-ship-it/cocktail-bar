## 二、技术选型与架构思路

### 2.1 为什么选 Express 而不是 Next.js API Routes 或 NestJS

| 方案 | 评估 |
|------|------|
| **Next.js API Routes** | 前端已经是纯 React，不想耦合——后端独立部署更灵活 |
| **NestJS** | 学习曲线陡，项目小不需要 DI/装饰器 |
| **Express（选用）** | 最简单、社区最大、中文资料最多、最适合学习 |

### 2.2 为什么选 PostgreSQL 而不是 MySQL 或 MongoDB

| 因素 | 决策 |
|------|------|
| JSONB 支持 | 鸡尾酒故事/方法是半结构化数据，JSONB 比 MySQL 的 JSON 列更好 |
| 数组列 TEXT[] | 配料/标签/场景直接存数组，无需关联表 |
| 生态 | Supabase 提供免费 PostgreSQL 托管 |
| 学习价值 | PostgreSQL 是行业标准，比 MySQL 更有竞争力 |

### 2.3 为什么用 pg 原生驱动不用 ORM（Prisma/Drizzle）

- **学习目的**：先理解原生 SQL，再学 ORM
- **代码量**：101 条数据的项目，手写 SQL 反而更快
- **控制力**：JSONB、数组、MD5 排序等高级用法在 ORM 里很别扭
- 以后可以迁移到 Prisma——SQL 基础打好了换 ORM 是降维

### 2.4 技术栈一览

| 技术 | 版本 | 用途 | 应用位置 |
|------|------|------|---------|
| Node.js | 22.x | 服务器运行时 | 整个后端 |
| Express | 5.2.x | HTTP 框架 | 路由 + 中间件 |
| pg | 8.x | PostgreSQL 客户端 | 数据库连接和查询 |
| dotenv | 最新 | 环境变量加载 | .env 文件读取 |
| cors | 2.x | 跨域中间件 | 全局允许前端请求 |
| fs（内置） | - | 文件系统 | 读取 JSON 数据文件 |

## 三、数据库设计

### 3.1 表结构（完整版）

```sql
CREATE TABLE cocktails (
  id SERIAL PRIMARY KEY,
  eng VARCHAR(100) UNIQUE NOT NULL,    -- 英文名（唯一标识）
  chn VARCHAR(200),                     -- 中文名
  cat VARCHAR(50),                      -- 分类：难忘经典/当代经典/新时代
  ingredients TEXT[],                   -- 配料数组
  story JSONB,                          -- 故事：{origin, funFact, legacy}
  method JSONB,                         -- 调制方法：{method, glass, steps[], garnish}
  taste_tags TEXT[],                    -- 口感标签
  difficulty INT DEFAULT 2,             -- 难度 1-4
  occasion TEXT[],                      -- 场景
  view_count INT DEFAULT 0,             -- 浏览计数
  tip TEXT,                             -- 实操提醒
  created_at TIMESTAMP DEFAULT NOW()
)

CREATE TABLE spirits (
  id SERIAL PRIMARY KEY,
  slug VARCHAR(50) UNIQUE NOT NULL,  -- URL 标识：gin/vodka/rum/tequila/whisky/brandy
  name VARCHAR(50),                  -- 中文名
  eng VARCHAR(50),                   -- 英文名
  emoji VARCHAR(10),                 -- 图标
  description TEXT,                  -- 简介
  hero TEXT,                         -- 大标题文案
  details JSONB                      -- 分类详情卡（酒款/品牌列表）
)

CREATE TABLE articles (
  id SERIAL PRIMARY KEY,
  title VARCHAR(200),
  cat VARCHAR(50),        -- 鸡尾酒历史/酿造工艺/基酒知识/调酒师故事/酒具百科/品鉴笔记
  author VARCHAR(50),
  read_time VARCHAR(20),
  summary TEXT,
  body TEXT,              -- 正文
  created_at TIMESTAMP DEFAULT NOW()
)
```

### 3.2 为什么用 JSONB 存 story 和 method

**story 结构示例：**
```json
{
  "origin": {
    "title": "干马天尼的起源",
    "body": "关于干马天尼的起源至少有三种说法..."
  },
  "funFact": {
    "title": "007 与马天尼",
    "body": "詹姆斯·邦德那句著名的..."
  },
  "legacy": {
    "title": "鸡尾酒之王的神话",
    "body": "没有任何一款鸡尾酒..."
  }
}
```

- 3 段故事各自有标题+正文，嵌套结构
- 用 JSONB 只需 1 列，不用建 2 张关联表
- `SELECT story->'origin'->>'title'` 可直接提取字段
- 灵活性：以后增加第 4 段故事不需要 ALTER TABLE

**method 结构示例：**
```json
{
  "method": "摇和法",
  "glass": "马天尼杯",
  "steps": ["将所有材料加入摇酒壶", "加冰用力摇晃10-15秒", "双重过滤倒入冰镇的马天尼杯中"],
  "garnish": "青柠片或青柠皮卷"
}
```

### 3.3 为什么用 TEXT[] 存配料和标签

- 配料是"读出来展示就行"的数据，不需要 JOIN 查询
- `unnest(ingredients)` 可以把数组展开为行，用于模糊匹配
- 如果用关联表（cocktails ↔ cocktail_ingredients ↔ ingredients），每次查酒都要 2 次 JOIN
- 用数组：一条 SQL 直接拿到所有配料

## 五、核心功能实现思路

### 5.1 多条件动态 SQL 构建

```js
app.get("/api/cocktails", async (req, res) => {
  const { spirit, search, taste, difficulty, occasion } = req.query
  let query = "SELECT * FROM cocktails"
  const params = []
  const conditions = []

  if (search) {
    params.push(`%${search}%`)
    conditions.push(`(eng ILIKE $${params.length} OR chn ILIKE $${params.length})`)
  }
  // spirit / taste / difficulty / occasion 同理...

  if (conditions.length > 0) {
    query += " WHERE " + conditions.join(" AND ")
  }

  query += " ORDER BY id"
  const result = await db.query(query, params)
  res.json(result.rows)
})
```

**设计要点：**
- `$${params.length}` 技巧：每次 push 后 params.length 恰好等于当前 `$N` 序号
- `conditions.join(" AND ")` 把所有筛选条件用 AND 连接
- 不用任何 SQL 字符串拼接用户输入——参数化防注入

### 5.2 智能搜索

用户输入 `"我有金酒和柠檬，能调什么？"`：

```js
// 步骤1：关键词匹配
const spiritMap = [
  { keys: ["金酒", "gin", "杜松子"], value: "金酒" },
  // ...
]
for (const s of spiritMap) {
  if (s.keys.some(k => q.toLowerCase().includes(k.toLowerCase()))) {
    parsed.spirits.push(s.value)
  }
}

// 步骤2：SQL 查询
// spirits → OR（任一匹配即可）
// tastes → AND（所有口味都要匹配）
// 维度间 → AND（基酒 AND 口味 取交集）
```

### 5.3 每日推荐（MD5 确定性随机）

```sql
SELECT * FROM cocktails ORDER BY MD5(eng || $1) LIMIT 1
```

- `$1` = 日期字符串 "2026-08-07"
- 同一天同一款酒——任何用户、任何地区都一样
- 没有真正的随机性——是确定性的、可预测的、可复现的

### 5.4 浏览计数

```js
app.post("/api/cocktails/:name/view", async (req, res) => {
  const result = await db.query(
    "UPDATE cocktails SET view_count = view_count + 1 WHERE eng = $1 RETURNING view_count",
    [req.params.name]
  )
  res.json({ view_count: result.rows[0].view_count })
})
```

- POST 而非 GET——因为这是一个"动作"（修改数据）
- `RETURNING view_count` 一次 SQL 同时完成更新+返回新值
- 前端 fire-and-forget：不 await 结果，不阻塞页面

## 六、增量数据更新策略

项目创建了多个数据 JSON 文件 + 增量更新脚本：

| 脚本 | 数据文件 | 作用 |
|------|---------|------|
| `setup-db.js` | `cocktails.json` + 内联数据 | 完整初始化（DROP + CREATE + INSERT） |
| `update-methods.js` | `cocktail-methods.json` | 加 method JSONB 列 + 写入调制方法 |
| `update-attributes.js` | `cocktail-attributes.json` | 加 taste_tags/difficulty/occasion/view_count |
| `update-tips.js` | `cocktail-tips.json` | 加 tip 列 + 写入实操提醒 |

**设计原则：**
- `setup-db.js`：给新环境用的完整初始化（本地/新服务器）
- `update-*.js`：给已有环境增量升级（线上 Supabase 不能 DROP TABLE）
- 所有脚本都用 `IF NOT EXISTS` 确保幂等（重复执行不报错）

### 新增技术点

**bcrypt 密码加密：**
```js
const bcrypt = require("bcryptjs")
// 加密（salt rounds = 10）
const hash = await bcrypt.hash(password, 10)
// 验证
const match = await bcrypt.compare(password, user.password_hash)
```
- 10 轮 salt 意味着攻击者暴力破解成本是普通哈希的 2^10 = 1024 倍
- bcrypt 天然抗彩虹表攻击（每个密码有随机 salt）
- 绝不存明文密码——即使数据库泄露密码也是安全的

**JWT 签发与验证：**
```js
const jwt = require("jsonwebtoken")
const JWT_SECRET = process.env.JWT_SECRET || "xxx"

// 签发（登录/注册成功后）
const token = jwt.sign(
  { id: user.id, email: user.email, nickname: user.nickname },
  JWT_SECRET,
  { expiresIn: "7d" }
)

// 验证（authMiddleware 中间件）
const decoded = jwt.verify(token, JWT_SECRET)
// decoded = { id, email, nickname, iat, exp }
```

**认证中间件模式：**
```js
function authMiddleware(req, res, next) {
  const header = req.headers.authorization
  if (!header?.startsWith("Bearer ")) {
    return res.status(401).json({ error: "请先登录" })
  }
  try {
    req.user = jwt.verify(header.split(" ")[1], JWT_SECRET)
    next()  // 放行
  } catch {
    return res.status(401).json({ error: "登录已过期" })
  }
}
```

**邮箱格式校验（正则）：**
```js
if (!/^[^\s@]+@[^\s@]+\.[^\s@]+$/.test(email)) {
  return res.status(400).json({ error: "请输入正确的邮箱格式" })
}
// 规则：必须有 @ → 必须有点 → 不能有空格 → 各部分不能为空
```

**ON CONFLICT upsert（浏览历史去重）：**
```sql
INSERT INTO view_history (user_id, cocktail_eng, viewed_at)
VALUES ($1, $2, NOW())
ON CONFLICT (user_id, cocktail_eng) DO UPDATE SET viewed_at = NOW()
-- 如果已存在 → 更新时间；不存在 → 插入
```

## 十二、Phase 8：学习与社区功能

### 学习卡片
- 静态卡片 70 张（手法/杯型/术语/基酒/配方/原料/历史/餐酒搭配）
- 自动生成 454 张鸡尾酒卡片（每款酒4张：基酒/手法/tip/口感）
- 合计 497 张卡片，覆盖 8 个分类
- 进度持久化：`flashcard_progress` 表，upsert 模式

### 调酒百科
- 7 个分类 43 个词条（手法/杯型/工具/术语/原料/历史/经典名酒）
- 可展开详情 + 关联词条 + 全文搜索
- 数据与学习卡片共享知识库，互为补充

### 评分系统
- 1-5 星评分 + 品鉴短评（200字以内）
- 一人一酒只能打一次分（upsert），可修改可删除
- 高分榜 `GET /api/ratings/top/list`（平均分+评分人数加权）

### 口味测试
- 6 道选择题（甜度/酸度/苦味/酒精度/口感/场景）
- 答案映射为口味权重 → SQL 匹配鸡尾酒 → 返回 TOP 5
- 结果可保存到 AI 用户记忆
